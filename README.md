Cyber Storefront

ონლაინ მაღაზიის ფრონტენდი, რომელიც რვა დავალებად (FE-001 – FE-008) ავაწყვე თანმიმდევრულად. შესვლიდან და კატალოგიდან დაწყებული, ყიდვით და ენის გადართვით დამთავრებული.

როგორ გავუშვა
bash
npm install
npm run dev

პროდუქციის ბილდისთვის (ტიპების შემოწმებასთან ერთად):

bash
npm run build

.env უკვე მზადაა:

env
VITE_API_URL=https://shop-api-kbe6.onrender.com/api
რა გავაკეთე

1. ავტორიზაციის ეკრანები და დიზაინ-სისტემა (FE-001)
ჯერ ავაწყვე საბაზისო კომპონენტები (Button, Input, PasswordInput, FormField, Alert, Badge, Skeleton, QuantityStepper), ფერები და ზომები კი ცალკე tokens.css-ში გავიტანე. მერე გავაკეთე /login, /register და /forgot-password. ფორმები React Hook Form-ითა და Zod-ითაა: შეცდომა იჩენს თავს გაგზავნისას, შემდეგ კი ველის შეცვლისთანავე ახლდება, ფოკუსი კი პირველ არასწორ ველზე გადადის. შესვლისას მხოლოდ იმას ვამოწმებ, რომ ველები შევსებულია, პაროლის სირთულეს არა.

2. API-სთან დაკავშირება (FE-002)
ყველა მოთხოვნა ერთ API კლიენტზე გადის (src/shared/api/client.ts). ის თვითონ აბამს ტოკენს და ამუშავებს 401 TOKEN_EXPIRED-ს. აპის გახსნისას GET /auth/me გადაწყვეტს, ვინ არის შესული, და სამი მდგომარეობა მაქვს (loading, authenticated, unauthenticated), ამიტომ F5-ზე ლოგინის გვერდი აღარ ციმციმებს. პაროლის აღდგენა სამ ბიჯად ერთ ეკრანზეა, resetToken კი მხოლოდ კომპონენტის მეხსიერებაში ინახება.

3. კატალოგი (FE-003)
კატეგორია (smartphones) ერთადერთ ადგილას, constants.ts-შია გაწერილი. ფილტრების პანელს დინამიკურად ვაგებ GET /categories/{slug}-ის პასუხით (checkbox, radio, color, range). ფილტრები, სორტირება, ძებნა (350ms debounce) და პაგინაცია URL-თანაა სინქრონიზებული, ამიტომ ბმულის გაზიარებაც მუშაობს. ძველ მოთხოვნებს AbortController აუქმებს.

4. პროფილი და მისამართები (FE-004)
PATCH /auth/me-ზე მხოლოდ შეცვლილი ველები იგზავნება, currentPassword-თან ერთად. თუ მიმდინარე პაროლი არასწორია (400 INVALID_CURRENT_PASSWORD), შეცდომა პირდაპირ იმ ველთან ჩანს და მომხმარებელი სისტემიდან არ გადის. მისამართებს აქვს სრული CRUD, ნაგულისხმევი მისამართის არჩევა და 10 მისამართის ლიმიტი.

5. კალათა (FE-005)
კალათა სერვერიდან მოდის და ერთ წყაროშია (TanStack Query ['cart']), ამიტომ ჰედერის ბეჯი, კალათის გვერდი და ჩექაუთი ყოველთვის ერთსა და იმავეს აჩვენებს. ყურადღება მივაქციე ერთ რამეს: დამატებისას POST /cart/items-ს productId ეგზავნება, ხოლო რაოდენობის შეცვლასა და წაშლაზე (PATCH/DELETE /cart/items/:id) კალათის პოზიციის item.id. lineTotal და subtotal სერვერისგან მოდის და პირდაპირ გამოიყენება, ფრონტზე არაფერს ვითვლი.

6. ჩექაუთი (FE-006)
/checkout-ზე მისამართი ნაგულისხმევით ივსება და შენახულ მისამართებს შორის გადართვაც შეიძლება. ბარათის ნომერი 4-4 ჯგუფად იყოფა და Luhn-ით მოწმდება, MM/YY-ში კი / თავისით ჩაიწერება. /checkout/confirm/:orderId-ზე შეკვეთა 6-ციფრიანი კოდით დასტურდება, ხელახლა გაგზავნას 30-წამიანი ტაიმერი აქვს, orderId კი URL-შია, ამიტომ F5 არაფერს აფუჭებს. ბოლოს არის /orders/:id (შეკვეთის გვერდი) და /orders (ისტორია).

7. პროდუქტის გვერდი (FE-007)
/product/:slug-ზე გალერეა იმდენ სურათს აჩვენებს, რამდენიც პროდუქტს აქვს, და კლავიატურის ისრებითაც იშლება. მახასიათებლების ცხრილი დინამიკურია და 360px-ზეც კარგად ჩანს. გვერდზე ჩანს მარაგი და გარანტია, ქვემოთ კი 8 მსგავსი პროდუქტი, იმავე ProductCard-ით. key={slug} უზრუნველყოფს, რომ სხვა პროდუქტზე გადასვლისას ძველი მდგომარეობა არ დარჩეს.

8. ორი ენა (FE-008)
ჰედერში ქართულ და ინგლისურს შორის გადართვა გვერდის გადატვირთვის გარეშე ხდება. ამასთან ერთად ახლდება <html lang>, არჩეული ენა ინახება localStorage-ში, ფასები და თარიღები კი Intl-ით ფორმატდება (src/shared/lib/format.ts).

არქიტექტურული გადაწყვეტილებების მიზეზები ADR.md-შია.
